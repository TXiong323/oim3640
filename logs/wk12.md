## What I learned this week
I learned the content of session 22, the flask lecture slides, and session 23. Session 22 and the flask lecture slides went over Flask forms and POST requests in more detail. I learned the modern way to write Flask routes using @app.get and @app.post instead of the older @app.route with methods=['GET', 'POST']. This is cleaner because each function only handles one HTTP method. I also learned the standard Flask project structure, where app.py has the routes, a helper file like mbta_helper.py has the API functions, templates/ has the HTML files, and static/ has the CSS. Session 23 was about deploying a Flask app to the internet. I learned that the Flask built-in server is only for development, and for production I need a real server like gunicorn plus a requirements.txt file that lists all the packages. I can deploy for free on Render or PythonAnywhere, and the app will have a real URL that anyone can visit. I also learned how to protect my API keys in production by setting environment variables in the Render dashboard instead of uploading the .env file. Finally I learned the difference between frontend, backend, and full stack, and that my MP3 is actually a full stack web app.

## Challenges I faced
Deploying to Render was harder than I expected. I forgot to add gunicorn to my requirements.txt the first time, so the build failed. Then I also forgot to set the environment variable for my API key in the Render dashboard, so my app crashed when it tried to read the key. I also learned the hard way that I should never set debug=True in production because it lets anyone run code on my server, which is a big security problem. The cold start on the free tier was also confusing at first because I thought my app was broken when it took 30 seconds to load, but actually it was just sleeping.
